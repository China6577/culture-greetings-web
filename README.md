# culture-greetings-web · 拾笺

基于文化感知的多智能体贺卡创作平台。所有新作品都通过 Agnes 真实生成：文本角色使用 `agnes-2.5-flash`，图片角色使用 `agnes-image-2.5-flash`，无模板检索、向量数据库、规则回退图片或模拟生成进度。

## 运行

本机只需 Docker Desktop。前端构建、Nginx、FastAPI 和普通 PostgreSQL 17 均在容器运行，不需要主机 Python 或 Node 环境。

1. 执行 `./scripts/setup-docker.ps1` 生成本地数据库密码。
2. 在忽略的 `.env` 文件中设置 `AGNES_API_KEY`。不要使用 `VITE_` 前缀，不要把密钥写入前端。
3. 执行 `docker compose up -d --build`。
4. 打开 [本地网站](http://127.0.0.1:5173)、[API 文档](http://127.0.0.1:5173/api/docs)。

完整项目名与 Compose name 均为 `culture-greetings-web`，所有容器、网络、镜像和卷使用此名称前缀。数据库不暴露主机端口。

## 使用

右上角选择国家，国家固定界面及默认创作文案语言。填写收件人、署名、可选的原文祝福，在描述框说明节日/场景、文化元素、配色、风格及不想出现的内容，点击生成。未填写祝福时由文本模型创作；填写后的原文由服务端保留，不能被角色改写。

生成页面展示实际角色事件，没有人为倒计时或虚构百分比。任务在后端队列持续执行，刷新带 job 参数的生成地址可恢复查询，离开页面后完成的作品自动进入“我的贺卡”。失败显示具体服务错误，没有模板或图片回退；重试一个已失败任务会建立新请求，可能产生新的 API 用量。

成品居中显示真实生成的插画及独立文字层，默认静态，可切换 H5 并分享作品链接。动效设计智能体会按用户描述、文化、节日及视觉方案生成动画参数：花瓣、星光、彩纸、烟花、柔光或无装饰效果，搭配独立的底图运动、配色、密度、方向和周期。网页使用经过验证的动画组件呈现，持续循环；文字不参与运动，装饰限制在插画区域或两侧边缘。系统减少动态效果时自动静止，列表缩略图不播放动画。已有未保存动效参数的作品保留原有轻微底图运动。

动效方案与作品一起持久化，分享后仍使用同一方案，不在查看时重新调用 AI。文字层保证姓名和原文准确，不依赖图片模型绘制汉字。作品及生成图片分别保存到数据库卷和 `generated-assets` 卷，重启容器后仍存在。

“我的贺卡”按创建时间倒序，每页 12 张，支持页码和上一页/下一页。删除需确认，随后删除记录和图片，原分享地址失效；末页为空时自动回退。当前为本地单用户应用，没有账户隔离。

创建页和作品列表均只显示一个统一样式的页面标题。列表右上角提供批量删除：进入后可勾选卡片、全选本页并查看选择数量，确认所选卡片清单后提交一次批量删除。翻页清空当前选择；取消选择恢复普通查看模式。单张删除按钮保留在卡片右下角，点击卡片本身查看作品。

## 协作流程

协调器锁定用户条件 → 需求解析 → 文化策划 → 文案创作 → 视觉设计 → 动效设计 → 方案审核 → Agnes 图片生成 → 图片完整性校验与持久化。各步骤从上到下依次完成，文案会读取已完成的文化方案；审核修订也按文案、视觉、动效、审核的顺序执行。

每个文本角色是独立的真实模型请求，有专属系统指令、输入输出 schema 和可追踪事件。审核不通过时最多协作修订一次；仍不通过则失败，不无限循环或悄悄回退。文化/风格/负向视觉条件通过提示词与方案审核控制，无法保证模型逐像素遵循；图片生成后的校验验证格式、大小与可解码性，不声称进行了图像语义验收。

普通 PostgreSQL 只存作品、任务、结构化角色成果。旧模板表、文化配置表、向量表和 vector 扩展已在迁移中移除；PyTorch、Transformers、Embedding 模型及缓存卷不再被项目依赖。

## 测试

```powershell
docker compose --profile tools run --build --rm tools npm test
docker compose exec api python -m pytest tests -q
```

单元测试使用明确隔离的 HTTP 传输替身和临时图片，测试失败路径及硬约束；应用运行时没有模拟开关。真实接入验收记录见 `docs/VALIDATION.md`。

## 迁移说明

按用户要求，`0004_agnes_agents` 迁移会永久清空以前的所有贺卡，并移除模板检索数据；浏览器升级时也清理旧卡和草稿缓存。此操作不迁移旧作品。不要执行 `docker compose down -v`，除非也要删除当前新作品和图片。
